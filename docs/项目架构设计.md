# ECO Agent 项目架构设计

本文档定义 ECO Agent（基于 LangGraph 的 ECO 固定流水线原型）的项目目录结构、模块职责、文件归属和开发约定。

设计原则来自《基于LangGraph的ECO固定流水线详细设计方案》：调用层与图代码分离、Step 粒度 MCP API、Mock 先行可切换、State 集中管理。

## 三、各模块职责与关键代码归属

### 3.1 src/main.py —— 入口文件

| 职责 | 说明 |
|---|---|
| 导入并编译图 | `from src.graph_builder import build_graph` → `graph = build_graph(checkpointer, mcp_server)` |
| MCP 切换点 | `USE_REAL_MCP = False` 开关，一行切换 Mock/真实 |
| Checkpointer 初始化 | SqliteSaver 或 MemorySaver |
| 调用层启动 | 调用 `calling_layer.event_loop.run()` 进入主循环 |
| 不做业务逻辑 | main.py 只有 import + 初始化 + 启动，不写节点/路由代码 |

### 3.2 src/state.py —— ECOState 定义

所有 21 个 State 字段集中在此，一个文件搞定：

```python
from typing import TypedDict

class ECOState(TypedDict):
    # === 基础参数 ===
    design_name: str
    run_dir: str
    iteration_cnt: int
    
    # === Phase1/2 Step 结果 ===
    setup_vio: int
    hold_vio: int
    pv_pass: bool
    signoff_pass: bool

    # === 报告路径 ===
                
    # === 中断相关 ===
    interrupt_msg: str
    user_fix_strategy: str
    user_iter_choice: str

    # === 状态跟踪 ===
    phase_status: dict
    step_status: dict
    current_phase: str
    current_step: str
    error_msg: str

    # === 收敛对比 ===
    prev_setup_vio: int
    prev_hold_vio: int

    # === 对话历史（复用 MessagesState） ===
    messages: list
```

### 3.3 src/graph_builder.py —— 图编排

唯一职责：**把所有节点和边组装成图并返回 compiled graph**。不实现节点逻辑，不写路由函数。

```python
def build_graph(checkpointer, mcp_server) -> CompiledStateGraph:
    builder = StateGraph(ECOState)

    # 1. 注册节点（传 mcp_server 给需要的节点工厂）
    builder.add_node("init", make_init_node())
    builder.add_node("run_eco_route", make_step_node(mcp_server, "run_eco_route", "phase1", ...))
    builder.add_node("run_ext", make_step_node(mcp_server, "run_ext", "phase1", ...))
    # ... 其他节点注册

    # 2. 入口
    builder.set_entry_point("init")

    # 3. 边和条件边
    builder.add_edge("init", "run_eco_route")
    builder.add_conditional_edges("run_eco_route", route_after_run_eco_route)
    # ... 其他边

    # 4. 编译
    return builder.compile(checkpointer=checkpointer)
```

**关键设计**：`make_step_node` 是一个工厂函数，返回一个闭包节点函数，闭包里已经绑定了 step_name / phase_name / result_keys / mcp_server，这样 builder.add_node 时只需要传闭包，不需要每次写 lambda。

### 3.4 src/nodes/ —— 节点实现

| 文件 | 包含的节点 | 对应设计文档 |
|---|---|---|
| `step_runner.py` | `_run_step(state, step_name, phase_name, result_keys, extra_params)` | 4.5 节统一辅助函数 |
| `node_init.py` | `make_init_node()` → 返回闭包 `node_init(state)` | 4.1 节 |
| `node_phase1.py` | `make_step_node(mcp_server, "run_eco_route", ...)` 和 `make_step_node(mcp_server, "run_ext", ...)` 的工厂函数 + `node_phase1_summary`（如果有的话） | 4.2 节 |
| `node_phase2.py` | run_sta / run_pv / run_signoff 三个 Step 工厂 + `node_phase2_summary` | 4.3 节 |
| `node_phase3.py` | run_fix_setup / run_fix_hold 工厂 + `node_phase3_summary` | 4.4 节 |
| `node_error_handler.py` | `make_error_handler_node()` → 返回闭包 `node_error_handler(state)` | 4.6 节 |
| `node_finalize.py` | `node_finalize(state)` | 4.7 节 |

**命名约定**：工厂函数用 `make_xxx_node()`，返回的闭包内部修改 State 并 return，闭包名用 `node_xxx`。Phase 的 Step 节点直接通过 `step_runner.py` 的工厂创建，不单独写闭包。

### 3.5 src/routers/phase_routes.py —— 路由函数

所有条件边的 path 参数集中在这里，一个文件 10 个函数：

```python
# Phase1
def route_after_run_eco_route(state) -> Literal["error_handler", "run_ext"]: ...
def route_after_run_ext(state) -> Literal["error_handler", "__parallel__"]: ...

# Phase2
def route_after_phase2_summary(state) -> Literal["error_handler", "run_fix_setup", "run_fix_hold"]: ...

# Phase3
def route_after_phase3_summary(state) -> Literal["init", "finalize"]: ...
```

**约束**：路由函数是纯函数——只读 State，不修改 State，不调 MCP API。

### 3.6 src/mcp_server/ —— MCP Server 两种实现

| 文件 | 职责 | 对应设计文档 |
|---|---|---|
| `protocol.py` | `class ECOMCPServer(Protocol)` —— 7 个方法签名 + 类型提示 | 7.6 节接口契约 |
| `mock.py` | `class MockECOMCPServer` —— 场景驱动 Mock 实现 | 7.6 节 Mock 实现 |
| `real.py` | `class RealECOMCPServer` —— subprocess 调真实 EDA 工具（Step 4 开发） | 7.6 节真实接入 |

**关键约束**：Mock 和 Real 都必须实现 Protocol 的 7 个方法，签名完全一致。`main.py` 的 `USE_REAL_MCP` 开关决定 import 哪个。

### 3.7 src/calling_layer/ —— 调用层（薄壳）

| 文件 | 职责 | 对应设计文档 |
|---|---|---|
| `event_loop.py` | 主循环：`while True: stream events → check interrupt → get input → Command resume/goto` | 6.2 节 event loop 伪代码 |
| `interrupt_handler.py` | 三种 interrupt 的格式化展示 + 用户输入解析：`handle_interrupt1()` / `handle_interrupt2()` / `handle_error_handler()` | 6.2、6.3 节 |
| `retry_strategy.py` | Error Handler retry 时：从 state["current_step"] 取出错 Step 名 → update_state 重置 step_status + 清 error_msg → Command(goto=step_to_retry) | 6.2 节 retry 逻辑（本轮修复） |
| `formatters.py` | `format_event(event)` / `format_state(state)` / `format_sta_comparison(prev, curr)` 等纯格式化函数 | 6.2 format_event 占位 |

**关键约束**：调用层**不 import LangGraph 内部的任何节点/路由函数/State 结构实现**——它只和 `graph`（编译后的 CompiledStateGraph）打交道，调 `stream()` / `get_state()` / `update_state()`。这样未来重构为 Typer CLI 时整个 calling_layer 可以直接替换，graph 代码一行不动。

### 3.8 src/conversation/ —— 对话路径

| 文件 | 职责 | 对应设计文档 |
|---|---|---|
| `agent.py` | `node_agent(state)` —— LLM + bind_tools + ToolNode 注册 | 2.1、5.2 节 |
| `tools.py` | ToolNode 注册的工具列表：`start_eco_pipeline`（意图分流）、其他对话工具 | 2.1、5.2 节 |

### 3.9 src/utils/ —— 通用工具

| 文件 | 职责 |
|---|---|
| `file_utils.py` | `ensure_dir(path)` / `check_write_permission(path)` / `build_log_path(run_dir, phase, step)` |
| `constants.py` | `VALID_FIX_STRATEGIES = {"phase1": "run_eco_route", "phase2": "run_sta", "phase3": "run_fix_setup"}` / `PHASE_STEPS_MAPPING` / `VALID_FIX_STRATEGIES = {"setup", "hold"}` |

```
                    ┌─────────────┐
                    │  pyproject   │
                    │  + .env      │
                    └──────┬──────┘
                           │
        ┌──────────────────┼──────────────────┐
        ▼                  ▼                  ▼
   ┌─────────┐       ┌──────────┐       ┌───────────────┐
   │  state  │       │ constants │       │ mcp_server/   │
   └────┬────┘       └────┬─────┘       └──────┬────────┘
        │                 │                     │
        ▼                 ▼                     │
   ┌────────────────────────┐                  │
   │      nodes/            │◄─────────────────┘
   │  (step_runner 依赖     │    nodes/step_runner 调 MCP API
   │   mcp_server 实例)     │
   └────────┬───────────────┘
            │
            ▼
   ┌────────────────────────┐
   │      routers/          │    路由函数只读 state，不依赖 nodes
   └────────┬───────────────┘
            │
            ▼
   ┌────────────────────────┐
   │    graph_builder.py    │    组装 nodes + routers → compiled graph
   └────────┬───────────────┘
            │
            ▼
   ┌────────────────────────┐
   │   calling_layer/       │    只依赖 compiled graph，不依赖 nodes/routers
   └────────┬───────────────┘
            │
            ▼
   ┌────────────────────────┐
   │      main.py           │    入口：初始化 → graph_builder → calling_layer
   └────────────────────────┘
```

**依赖方向**（严格单向，禁止反向）：

| 依赖方 | 被依赖方 |
|---|---|
| `nodes/step_runner.py` | `state`、`mcp_server`（传入的实例）、`utils` |
| `routers/phase_routes.py` | `state`、`utils/constants`（只读） |
| `graph_builder.py` | `state`、`nodes/`、`routers/`、`utils` |
| `calling_layer/ | **只依赖** `langgraph` 类型 + `utils/constants`（VALID_FIX_STRATEGIES），**不依赖** nodes/routers/graph_builder），**不依赖** nodes/routers/graph_builder |
| `main.py` | `graph_builder`、`calling_layer`、`mcp_server`（Mock/Real 二选一）、`config` |

**为什么调用层不依赖 graph_builder**：调用层只和 `CompiledStateGraph`（编译后的可执行图）打交道。如果调用层 import 了 nodes/routers，那重构为 Typer CLI 时就会牵一发而动全身——违反设计文档 6.1 节"调用层可独立替换"的约束。

## 十、编码约定

| 约定 | 说明 |
|---|---|
| 节点函数签名 | 所有 LangGraph 节点闭包签名统一为 `def node_xxx(state: ECOState) -> dict:`（返回 State 的更新 dict，不 mutate 原始 state） |
| 路由函数签名 | 统一为 `def route_after_xxx(state: ECOState) -> Literal["node_a", "node_b", ...]:` 或 `-> list[Literal["node_a", ...]]`（Send 并行时） |
| State 更新方式 | **禁止** `state["setup_vio"] = 123`；**必须** `{"setup_vio": 123, ...}` 作为返回值，LangGraph 自动合并 |
| 异常处理 | 节点内部只 try-except `_run_step`（调用 MCP 的地方），其他代码不 try-except；异常类型统一为 `Exception` 子类 |
| 日志 | 原型阶段 `print()` + `logging.basicConfig(level=logging.INFO)` 够用；不引入重型日志框架 |
| import 规范 | 每个文件顶部只 import 自己直接依赖的模块；禁止 `import *`；LangGraph 类型注解用 `from __future__ import annotations` |
| 常量 | 所有跨文件共享的常量放 `src/utils/constants.py`，禁止在多个文件里重复定义 |
