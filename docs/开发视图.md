# ECO Agent 项目架构设计

本文档定义 ECO Agent（基于 LangGraph 的 ECO 固定流水线原型）的项目目录结构、模块职责、文件归属和开发约定。

设计原则来自《基于LangGraph的ECO固定流水线详细设计方案》：调用层与图代码分离、Step 粒度 MCP API、Mock 先行可切换、State 集中管理。

**架构优化说明**（开发过程中迭代引入）：
- `node_gates.py`：phase2_gate / phase3_gate 解决 Send 并行 + 多目标条件边的 race condition
- `node_error_handler.py` 内部 Command(goto)：绕开 checkpoint metadata 残留导致的额外 interrupt
- calling_layer 极度简化：所有中断统一 `Command(resume=user_input)`，Command(goto) 由节点内部返回
- `config_loader.py` / `checkpoint_config.py` / `formatters.py` / `agent.py` / `node_gates.py` 是开发过程中自然演进的模块，设计文档初始骨架未提及

## 三、各模块职责与关键代码归属

### 3.1 src/main.py —— CLI 入口

| 职责 | 说明 |
|---|---|
| YAML 配置加载 | `argparse --config` → `config_loader.load_config()` → deep merge 默认值 |
| Checkpointer 初始化 | 根据 `checkpoint.backend` 创建 MemorySaver 或 SqliteSaver |
| 图编译 | `build_graph(checkpointer, MockECOMCPServer(scenario=...))`（原型阶段用 Mock） |
| 调用层启动 | `event_loop.run(graph, config)` |
| 不做业务逻辑 | main.py 只有 argparse + 初始化 + 启动 |

**原型阶段简化**：`main.py` 硬编码用 MockECOMCPServer，真实 EDA 接入时替换为 RealECOMCPServer（Step 4）。没有 `USE_REAL_MCP` 开关——原型阶段不需要。

### 3.2 src/state.py —— ECOState 定义

所有 23 个 State 字段集中在此，使用 `TypedDict` + `Annotated` reducers：

```python
from typing import TypedDict, Annotated
from operator import add

def _last_writer_reducer(existing, updates):
    return updates

def _dict_merge_reducer(existing, updates):
    return {**existing, **updates}

class ECOState(TypedDict, total=False):
    # === 基础参数 ===
    design_name: str
    design_dir: str                    # ★ 架构扩展
    run_dir: str
    iteration_cnt: int
    
    # === Phase1/2 Step 结果 ===
    setup_vio: int
    hold_vio: int
    pv_pass: bool
    signoff_pass: bool

    # === 中断相关 ===
    interrupt_msg: str
    user_fix_strategy: str
    user_iter_choice: str
    user_error_choice: str             # ★ error_handler 架构扩展
    retry_step: str                    # ★ error_handler 架构扩展

    # === 状态跟踪（dict 字段用 _dict_merge_reducer，Phase2 并行时三个节点各自更新不同 key） ===
    phase_status: Annotated[dict[str, str], _dict_merge_reducer]
    step_status: Annotated[dict[str, str], _dict_merge_reducer]
    step_elapsed: Annotated[dict[str, float], _dict_merge_reducer]  # ★ step_runner 耗时追踪
    current_phase: str
    current_step: str
    error_msg: str

    # === 收敛对比 ===
    prev_setup_vio: int
    prev_hold_vio: int
    iteration_history: Annotated[list[dict], _dict_merge_reducer]    # ★ phase3_summary 迭代历史

    # === 对话历史（复用 MessagesState） ===
    messages: Annotated[list, add_messages]
```

**Reducer 策略说明**：
- `_last_writer_reducer`：覆盖式合并，适用于单值字段（setup_vio / hold_vio / run_dir 等）
- `_dict_merge_reducer`：字典键级合并，适用于 phase_status / step_status / step_elapsed（Phase2 并行三个节点同时更新 step_status 的不同 key：run_sta→step_status["run_sta"]="done"、run_pv→step_status["run_pv"]="done"、run_signoff→step_status["run_signoff"]="done"，需要合并而不是覆盖）
- `add_messages`：LangGraph 标准 messages reducer，list 追加

### 3.3 src/graph_builder.py —— 图编排

唯一职责：**把所有节点和边组装成图并返回 compiled graph**。不实现节点逻辑，不写路由函数。

```python
def build_graph(checkpointer, mcp_server) -> CompiledStateGraph:
    builder = StateGraph(ECOState)

    # 1. 注册节点
    builder.add_node("agent_entry", make_agent_entry_node())         # ★ 正式入口
    builder.add_node("init", make_init_node())
    builder.add_node("run_eco_route", make_step_node(mcp_server, "run_eco_route", "phase1", ...))
    builder.add_node("run_ext", make_step_node(mcp_server, "run_ext", "phase1", ...))
    builder.add_node("run_sta", make_step_node(mcp_server, "run_sta", "phase2", ...))
    builder.add_node("run_pv", make_step_node(mcp_server, "run_pv", "phase2", ...))
    builder.add_node("run_signoff", make_step_node(mcp_server, "run_signoff", "phase2", ...))
    builder.add_node("phase2_gate", make_phase2_gate_node())        # ★ Gate 汇聚
    builder.add_node("phase2_summary", make_phase2_summary_node())
    builder.add_node("run_fix_setup", make_step_node(mcp_server, "run_fix_setup", "phase3", ...))
    builder.add_node("run_fix_hold", make_step_node(mcp_server, "run_fix_hold", "phase3", ...))
    builder.add_node("run_fix_leakage", make_step_node(mcp_server, "run_fix_leakage", "phase3", ...))
    builder.add_node("phase3_gate", make_phase3_gate_node())        # ★ Gate 汇聚
    builder.add_node("phase3_summary", make_phase3_summary_node())
    builder.add_node("error_handler", make_error_handler_node())    # ★ 内部 Command(goto)
    builder.add_node("finalize", make_finalize_node())

    # 2. 入口
    builder.set_entry_point("agent_entry")                           # ★ agent_entry 为正式入口

    # 3. 边和条件边
    builder.add_conditional_edges("agent_entry", route_after_agent_entry)
    builder.add_conditional_edges("init", route_after_init)
    builder.add_edge("run_eco_route", "run_ext")
    builder.add_conditional_edges("run_ext", route_after_run_ext)    # 返回 Send 并行
    builder.add_edge("run_sta", "phase2_gate")                      # ★ 三条都连 gate
    builder.add_edge("run_pv", "phase2_gate")
    builder.add_edge("run_signoff", "phase2_gate")
    builder.add_conditional_edges("phase2_gate", route_after_phase2_gate)  # ★ 单一条件路由
    builder.add_conditional_edges("phase2_summary", route_after_phase2_summary)
    builder.add_edge("run_fix_setup", "phase3_gate")                 # ★ 三条都连 gate
    builder.add_edge("run_fix_hold", "phase3_gate")
    builder.add_edge("run_fix_leakage", "phase3_gate")
    builder.add_conditional_edges("phase3_gate", route_after_phase3_gate)
    builder.add_conditional_edges("phase3_summary", route_after_phase3_summary)
    builder.add_edge("finalize", END)
    # ★ error_handler 不加条件边！节点内部返回 Command(goto=target, update=reset)

    # 4. 编译
    return builder.compile(checkpointer=checkpointer)
```

**关键设计**：`make_step_node` 是一个工厂函数，返回一个闭包节点函数，闭包里已经绑定了 step_name / phase_name / result_keys / mcp_server，这样 builder.add_node 时只需要传闭包，不需要每次写 lambda。

### 3.4 src/nodes/ —— 节点实现

| 文件 | 包含的节点 | 对应设计文档 |
|---|---|---|
| `step_runner.py` | `_run_step(state, step_name, phase_name, result_keys, extra_params)` | 4.5 节统一辅助函数 |
| `node_init.py` | `make_init_node()` → 返回闭包 `node_init(state)` | 4.1 节 |
| `node_phase1.py` | `make_step_node(mcp_server, "run_eco_route", ...)` 和 `make_step_node(mcp_server, "run_ext", ...)` 的工厂函数 + `node_phase1_summary`（如果有的话） | 4.2 节 |
| `node_phase2.py` | run_sta / run_pv / run_signoff 三个 Step 工厂 + `node_phase2_summary` | 4.3 节 |
| `node_phase3.py` | run_fix_setup / run_fix_hold 工厂 + `node_phase3_summary` | 4.4 节 |
| `node_error_handler.py` | `make_error_handler_node()` → 返回闭包 `node_error_handler(state)` | 4.6 节 |
| `node_finalize.py` | `node_finalize(state)` | 4.7 节 |

**命名约定**：工厂函数用 `make_xxx_node()`，返回的闭包内部修改 State 并 return，闭包名用 `node_xxx`。Phase 的 Step 节点直接通过 `step_runner.py` 的工厂创建，不单独写闭包。

### 3.5 src/routers/phase_routes.py —— 路由函数

所有条件边的 path 参数集中在这里：

```python
# agent_entry
def route_after_agent_entry(state) -> Literal["init", "__end__"]: ...

# Init
def route_after_init(state) -> Literal["run_eco_route", "error_handler"]: ...

# Phase1 串行
def route_after_run_ext(state) -> list[Send]: ...
# ★ 返回 Send 并行，arg 用共享字段白名单：
# _PHASE2_SHARED_KEYS = ("design_name", "design_dir", "run_dir",
#                        "iteration_cnt", "prev_setup_vio", "prev_hold_vio",
#                        "iteration_history", "step_elapsed")

# Phase2 Gate 汇聚后 — 单一条件路由
def route_after_phase2_gate(state) -> Literal["error_handler", "phase2_summary"]: ...
# ★ 任意并行 Step error → error_handler（方案 A：全阻断，无警告级）

# Phase2 Summary → Phase3 互斥分支
def route_after_phase2_summary(state) -> Literal["run_fix_setup", "run_fix_hold", "run_fix_leakage", "error_handler"]: ...

# Phase3 Gate 汇聚后 — 单一条件路由
def route_after_phase3_gate(state) -> Literal["error_handler", "phase3_summary"]: ...

# Phase3 Summary → 迭代循环 或 结束
def route_after_phase3_summary(state) -> Literal["init", "finalize"]: ...
```

**约束**：路由函数是纯函数——只读 State，不修改 State，不调 MCP API。

**Send 共享字段白名单**（`route_after_run_ext` 使用）：Phase2 Send 并行时只传 `_PHASE2_SHARED_KEYS` 子集给每个并行节点，避免并行节点互相覆盖各自独立更新的字段（如 setup_vio、hold_vio、pv_pass）。

### 3.6 src/mcp_server/ —— MCP Server 两种实现

| 文件 | 职责 | 对应设计文档 |
|---|---|---|
| `protocol.py` | `class ECOMCPServer(Protocol)` —— 7 个方法签名 + 类型提示 | 7.6 节接口契约 |
| `mock.py` | `class MockECOMCPServer` —— 场景驱动 Mock 实现 | 7.6 节 Mock 实现 |
| `real.py` | `class RealECOMCPServer` —— subprocess 调真实 EDA 工具（Step 4 开发） | 7.6 节真实接入 |

**关键约束**：Mock 和 Real 都必须实现 Protocol 的 7 个方法，签名完全一致。`main.py` 的 `USE_REAL_MCP` 开关决定 import 哪个。

### 3.7 src/calling_layer/ —— 调用层（薄壳）

| 文件 | 职责 |
|---|---|
| `event_loop.py` | **28 行主循环**：`while True: stream events → get_state → check interrupt → format → input → Command(resume=user_input)` |
| `formatters.py` | `format_event()` / `format_interrupt()` / `format_final_state()` 三个纯格式化函数 |

**★ 架构简化**（开发过程中迭代）：初始设计 60+ 行 event_loop + interrupt_handler.py + retry_strategy.py（调用层区分中断类型、做 update_state + Command(goto)），后来 error_handler 路由下沉到节点内部（节点返回 Command(goto=target, update=reset)），调用层简化为**所有中断统一 Command(resume=user_input)**，Command(goto) 由各节点内部返回。

**关键约束**：调用层**不 import LangGraph 内部的任何节点/路由函数/State 结构实现**——它只和 `graph`（编译后的 CompiledStateGraph）打交道，调 `stream()` / `get_state()`。这样未来重构为 Typer CLI 时整个 calling_layer 可以直接替换，graph 代码一行不动。

### 3.8 src/conversation/ —— 对话路径

| 文件 | 职责 |
|---|---|
| `agent.py` | `make_agent_entry_node()` — LLM/规则双重意图识别 + design_name 提取 + chat_fallback 路由（意图非 ECO 时终止对话） |

**实现方式**：支持规则匹配（直接从 messages 提取 design_name）和 LLM 两种路径，优先规则匹配（快、确定），规则匹配失败时走 LLM。没有使用 LangChain ToolNode——原型阶段意图分流简单，规则 + LLM 足够。

### 3.9 src/utils/ —— 通用工具

| 文件 | 职责 |
|---|---|
| `constants.py` | `STEP_TO_PHASE` / `VALID_STEP_TARGETS` / `VALID_FIX_STRATEGIES` / `INITIAL_PHASE_STATUS` 等常量 |
| `config_loader.py` | YAML 加载 + deep merge（默认值 ← 用户配置）+ `DEFAULTS` dict 定义默认配置 |
| `checkpoint_config.py` | Checkpoint 工厂：根据 `checkpoint.backend` 配置返回 MemorySaver 或 SqliteSaver |
| `file_utils.py` | `ensure_dir(path)` / `check_write_permission(path)` / `validate_design_dir(path)` / `find_design_files(path)` |

## 十、编码约定

| 约定 | 说明 |
|---|---|
| 节点函数签名 | 所有 LangGraph 节点闭包签名统一为 `def node_xxx(state: ECOState) -> dict:`（返回 State 的更新 dict，不 mutate 原始 state） |

| State 更新方式 | **禁止** `state["setup_vio"] = 123`；**必须** `{"setup_vio": 123, ...}` 作为返回值，LangGraph 自动合并 |

## 十一、架构演进策略（流程可配置性）

### 11.1 核心决策：3~5 个固定流程 → 硬编码 + 公共辅助函数

**问题**：当前 ECO 流程被固化成 LangGraph 图。未来如果需要支持 3~5 个固定业务流程，是应该继续硬编码还是引入 YAML 声明拓扑？

**决策**：维持硬编码（每个流程一个独立的 builder 函数）+ 抽公共辅助函数消除重复。**不引入 YAML 声明拓扑**。

**决策日期**：2026-09-13（原型开发收尾阶段）

---

### 11.2 决策依据

#### 为什么不选 YAML 声明拓扑？

每个业务流程**几乎一定会有独特细节**，这些细节用 YAML 很难优雅表达：

| 细节 | YAML 表达方式 | 问题 |
|---|---|---|
| Phase2 Send 用共享字段白名单（不传完整 state） | `send_shared_keys: [design_name, run_dir, ...]` | 跑通但如果某个流程 Send arg 要做 transform（如 `.upper()`），YAML 开始崩 |
| Phase3 三条普通边全注册（LangGraph 要求所有可达路径） | `steps: [a, b, c]` + `type: branch` | OK，但如果某个流程 Phase3 只注册两条边呢？YAML 没有表达力 |
| error_handler 不加任何边（节点内部 Command(goto)） | `edges: none` 或 `self_routing: true` | 每加一个 LangGraph 高级特性，YAML schema 膨胀一点 |
| 某个 Phase 不需要 interrupt | `skip_interrupt: true` | OK，但如果某个流程 Phase2 summary 不是中断而是条件路由到 finalize 呢？ |

**YAML 的根本问题**：通用 Builder 为了覆盖"几乎一定会有的例外"，会膨胀到变成一个不完整的 Python 解释器。花了 YAML 的维护成本，但没拿到 YAML 的简洁。

#### 为什么硬编码 + 公共辅助函数好？

| 维度 | 优势 |
|---|---|
| LangGraph 特性 100% 覆盖 | Send 共享字段白名单、Gate 自定义判断、三条普通边全注册、Command(goto) 返回类型——想用什么用什么，不受 schema 限制 |
| IDE 完美支持 | `builder.add_edge("run_sta", "phase2_gate")` 是符号，可跳转/重构/类型检查 |
| 调试友好 | 断点下到具体 builder，一眼看清走了哪条边；YAML 需要跨三层跳（YAML → Builder → 生成图） |
| Git diff 清晰 | 边从 A 改到 B，diff 就是一行改动；YAML schema 膨胀时 diff 噪声大 |
| 爆炸半径小 | 改 hold_only builder → 只有 hold_only 崩；改 YAML 通用 Builder → 所有流程全崩 |
| DRY 通过公共辅助函数解决 | `_wire_core_components()` / `_wire_parallel_phase()` / `_wire_branch_phase()` 消除重复，每个流程 builder 只剩"声明差异" |

**硬编码反而是最诚实的选择**——每个流程的拓扑就是 Python 代码，想加什么 LangGraph 特性加什么。

---

### 11.3 演进分层

#### Layer 0：当前（1 个流程，硬编码）

```python
# src/graph_builder.py —— 单流程硬编码
def build_graph(mcp_server, checkpointer):
    builder = StateGraph(ECOState)
    builder.add_node(...)
    builder.add_edge(...)
    builder.add_conditional_edges(...)
    return builder.compile(checkpointer=checkpointer)
```

#### Layer 1：3~5 个固定流程（硬编码 + 公共辅助函数）

```python
# src/graph_builders.py —— 多流程，公共辅助函数消除重复

def _wire_core_components(builder, mcp_server):
    """注册 agent_entry / init / error_handler / finalize + Phase1 串行"""

def _wire_parallel_phase(builder, step_names, gate_name, phase_name):
    """N 个并行 Step → Gate 汇聚 → 条件路由"""

def _wire_branch_phase(builder, step_names, gate_name, phase_name, router):
    """M 个互斥分支 → Gate 汇聚 → 条件路由"""

# ============ 每个流程 builder 只写"声明差异" ============

def build_default_eco(mcp_server, checkpointer):
    builder = StateGraph(ECOState)
    _wire_core_components(builder, mcp_server)
    _wire_parallel_phase(builder, ["run_sta", "run_pv", "run_signoff"], "phase2_gate", "phase2")
    builder.add_node("phase2_summary", make_phase2_summary_node())
    builder.add_conditional_edges("phase2_summary", route_after_phase2_summary)
    _wire_branch_phase(builder, ["run_fix_setup", "run_fix_hold", "run_fix_leakage"],
                       "phase3_gate", "phase3", route_after_phase2_summary)
    builder.add_node("phase3_summary", make_phase3_summary_node())
    builder.add_conditional_edges("phase3_summary", route_after_phase3_summary)
    builder.set_entry_point("agent_entry")
    builder.add_edge("finalize", END)
    return builder.compile(checkpointer=checkpointer)

def build_hold_only(mcp_server, checkpointer):
    """简化版：Phase2 只跑 STA + PV，Phase3 只跑 fix_hold，硬路由不中断"""
    builder = StateGraph(ECOState)
    _wire_core_components(builder, mcp_server)
    _wire_parallel_phase(builder, ["run_sta", "run_pv"], "phase2_gate", "phase2")
    builder.add_node("phase2_summary", make_phase2_summary_node(skip_interrupt=True))
    _wire_branch_phase(builder, ["run_fix_hold"], "phase3_gate", "phase3",
                       lambda s: "run_fix_hold")
    builder.add_node("phase3_summary", make_phase3_summary_node(force_stop=True))
    builder.set_entry_point("agent_entry")
    builder.add_edge("finalize", END)
    return builder.compile(checkpointer=checkpointer)

def build_regression_only(mcp_server, checkpointer):
    """验证版：Phase2 全部跑，跳过 Phase3，Phase2_summary → finalize"""
    builder = StateGraph(ECOState)
    _wire_core_components(builder, mcp_server)
    _wire_parallel_phase(builder, ["run_sta", "run_pv", "run_signoff"], "phase2_gate", "phase2")
    builder.add_node("phase2_summary", make_phase2_summary_node(skip_interrupt=True))
    builder.add_edge("phase2_summary", "finalize")  # 普通边，跳过 Phase3
    builder.set_entry_point("agent_entry")
    builder.add_edge("finalize", END)
    return builder.compile(checkpointer=checkpointer)
```

**新增流程成本**：复制一个 builder → 改差异部分 → ~10 分钟，不影响现有流程。

#### Layer 2：20+ 个流程（YAML + 硬编码逃生舱）

当流程数量膨胀到 20+，且其中大部分是标准变体（没有独特细节）时，考虑引入 YAML 声明。

**但必须保留硬编码作为逃生舱**——YAML 搞不定的复杂流程（有独特 Send 白名单、特殊 Gate 逻辑、自定义 Command(goto)）继续硬编码。公共辅助函数（`_wire_core_components` / `_wire_parallel_phase` / `_wire_branch_phase`）本身就是 YAML Builder 的基础，演进路径连续。

```python
# 注册机制：YAML 和硬编码并存
PIPELINE_REGISTRY = {
    "default":    build_default_eco,           # 硬编码
    "hold_only":  build_hold_only,             # 硬编码
    "hold_heavy": build_from_yaml("hold_heavy.yaml"),  # YAML
    "lvs_light":  build_from_yaml("lvs_light.yaml"),   # YAML
    "custom_xxx": build_custom_xxx,            # 硬编码逃生舱
}
```

#### Layer 3：流程本身不确定（LLM 驱动动态编排）

当业务流程本身不确定（"我想做 ECO 但不确定先跑 STA 还是先跑 ERC，你帮我决定"），不应该用固定图——换架构到 LangGraph ToolNode Agent：

```python
@tool
def run_sta(design_name: str, run_dir: str) -> dict: ...

@tool
def run_fix_setup(design_name: str, run_dir: str, fix_strategy: str) -> dict: ...

agent = create_tool_calling_agent(llm, [run_sta, run_pv, run_fix_setup, ...])
```

**这不是演进，是换架构**。从"固定图 → LLM Agent"跳跃需要完全不同的测试策略（LLM 行为不可预测）。当前固定图作为"确定性保底"，Agent 作为"灵活性补充"——两者可以并存。

---

### 11.4 演进路径拐点

| 流程数量 | 推荐方案 | 核心指标 |
|---|---|---|
| **1~10 个** | **硬编码 + 公共辅助函数**（Layer 1） | 每个流程 builder ≤ 80 行；公共辅助函数 ≤ 50 行/个 |
| 10~20 个 | 混合：简单流程用 YAML，复杂流程硬编码 | YAML schema 不超过 50 个字段；硬编码作为逃生舱 |
| 20+ 个 | YAML 声明 + 硬编码逃生舱（Layer 2） | 超过 70% 流程能用 YAML 覆盖 |
| 流程本身不确定 | ToolNode Agent（Layer 3） | 业务场景不再是"固定流水线" |

**演进是连续的**：Layer 1 的公共辅助函数就是 Layer 2 YAML Builder 的基础。Layer 2 的注册机制（`PIPELINE_REGISTRY`）不影响 Layer 1 的硬编码流程。

### 11.5 未来可配置化预存设计（轻量抽象）

当前 Layer 1 阶段，以下预存设计为未来演进留好口子（~30 行改动，可立即实施）：

```python
# constants.py —— Phase 步骤清单（公共辅助函数的输入）
PHASE_STEPS = {
    "phase1": ("run_eco_route", "run_ext"),
    "phase2": ("run_sta", "run_pv", "run_signoff"),
    "phase3": ("run_fix_setup", "run_fix_hold", "run_fix_leakage"),
}

# nodes/node_gates.py —— gate 工厂化（从硬编码 expected_steps 改为参数化）
def make_gate_node(phase_name: str, expected_steps: tuple[str, ...]):
    def gate(state: ECOState) -> dict:
        return _phase_gate(state, phase_name, expected_steps)
    return gate

# graph_builder.py —— 用 make_gate_node(PHASE_STEPS["phase2"]) 替代硬编码 node_phase2_gate
```

这样 Phase2 加 run_erc 只需改 `PHASE_STEPS["phase2"]` 加一个名字，不需要改 gate 节点代码。这是 Layer 1 内部的 DRY 优化，**不是 Layer 2 的 YAML**。
